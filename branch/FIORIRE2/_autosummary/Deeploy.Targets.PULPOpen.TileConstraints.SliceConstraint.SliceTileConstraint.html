static computeInputCubeFromOutputCube(outputCube: HyperRectangle, parseDict: Dict) → HyperRectangle

Return the input bounding box of outputCube in full-tensor coordinates.

outputCube.offset must be expressed in full output coordinates. For every axis the selected input elements are first, first + step, ..., last with first = start + offset * step and last = first + (size - 1) * step; the box spans min(first, last) and |last - first| + 1.

static computeLocalInputCubeFromOutputCube(outputCube: HyperRectangle, parentOutputDims: Tuple[int, ...], parseDict: Dict) → HyperRectangle

Return the input bounding box of outputCube relative to its parent input tile.

outputCube.offset is relative to a parent output tile of extent parentOutputDims, and the parent input buffer holds exactly the bounding box of that parent output tile (it was produced by computeInputCubeFromOutputCube() or by this method one level up). The slice start is therefore already contained in the parent buffer and must not be applied again:

  • step > 0: the parent box starts at the parent’s first selected element, so the local offset is off * step.

  • step < 0: the parent box starts at the parent’s last selected element, so the local offset is measured from the end of the parent output tile: (P - off - size) * |step|.

The extent is (size - 1) * |step| + 1 in both cases.

static inputLevelIndex(tilingSolution: NodeMemoryConstraint, targetMemLevel: str, operatorRepresentation: Dict[str, str | Any]) → int

Position of targetMemLevel in the memory path of data_in (-1 if absent).

A tensor’s memoryConstraints are ordered from its home level, which holds the full tensor, towards the compute level, and data_in tiles at targetMemLevel are cut from the level just before it. Index 1 therefore means the parent buffer is the full tensor (first tiling level), index >= 2 means the parent is an input tile of the enclosing tiling level, and 0/-1 mean the input is not transferred into targetMemLevel at all and is read in place.

classmethod serializeTilingSolution(tilingSolution: NodeMemoryConstraint, absoluteOutputCubes: List[AbsoluteHyperRectangle], targetMemLevel: str, ctxt: NetworkContext, operatorRepresentation: Dict[str, str | Any]) → Tuple[VariableReplacementScheme, TilingSchedule]

Serialize the output tiles of one parent tile.

wrapTilingSolution calls this once per parent output tile, with that parent’s children in absoluteOutputCubes. cube.rectangle.offset is relative to the parent output tile and cube.absoluteOffset is relative to the full output tensor. Two cases:

  • The parent data_in buffer is the full input tensor (first tiling level): the input cube is the global bounding box computed from the absolute output offset, which includes the slice start.

  • The parent data_in buffer is itself a tile (nested tiling, e.g. L3 -> L2 -> L1): it is the bounding box of the parent output tile, so the input cube is computed relative to it and the start is not added again. The parent output extent per axis is max(offset + dims) over the children, since they partition the parent (computeTileHyperRectangles), including partial edge tiles.

In both cases slice_start_k is local to the transferred input tile: 0 for step > 0 (the box starts at the first selected element) and dims - 1 for step < 0 (it ends there). If the input is not transferred at all (resident at the target level), the kernel indexes the full tensor, so the full input shape and the global first index are used instead.
